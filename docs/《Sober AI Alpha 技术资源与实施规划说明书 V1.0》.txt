一、项目目标定义
1.1 产品定位

Sober AI 不是普通聊天机器人，也不是角色卡平台，而是一个：

以单角色为核心的真人感 AI 数字伴侣产品

第一阶段重点不是“功能很多”，而是做出以下感受：

有一个固定角色
她会听你说话
她会停顿思考
她会自然开口回应
她有表情和轻微身体动作
她记得你
她有陪伴感
她支持偏成人向、亲密向、NSFW 内容
1.2 第一阶段目标（已确认）

阶段：内测 Alpha

规模：

你自己
朋友
总人数 ≤ 10

目标：

验证沉浸感是否成立
验证用户是否愿意持续回来和她说话
验证实时语音 + 真人感视觉 + NSFW 陪伴是否成立
1.3 第一阶段产品形式（已确认）

不是完整3D房间，而是：

全屏沉浸式真人伴侣界面

参考你发的截图形式：

屏幕主体是角色
中间有交互按钮 / 语音输入触发
角色处于固定视角
平时有轻微待机动作
说话时有口型 / 表情 / 微动作
思考时有单独状态
特殊内容再扩展到跳舞 / 换装 / 剧情片段

6.3 LLM 层
你的关键问题

你说得很对：

YeYe AI 现在上下文很长，响应慢

所以 Sober AI 一开始就必须重构上下文策略。

推荐原则
不要做

每一轮请求都塞入：

完整人设
完整历史聊天
完整设定文本

这样会让本地模型和外部 API 都变慢。

必须做
Context 压缩 / 记忆检索架构

改成：

用户发言
↓
拉取最近短对话
↓
拉取高优先级长期记忆
↓
拉取当前关系状态
↓
构建紧凑上下文
↓
送入 LLM
模型建议（Alpha阶段）

考虑到：

你有 5090 36GB
需要 NSFW
需要低延迟
用户数少

推荐方向是：

本地/云端自部署主模型
14B ～ 32B 量级的模型
使用量化版本
优先选“快且比较听话”的模型
商业API作为备用

作用：

复杂测试
质量对照
某些特殊场景 fallback
5090 在项目中的定位

我建议：

5090 优先给 LLM

因为：

你的产品核心竞争力是“角色大脑”
NSFW 需要可控
响应时间要更短
商业 API 不可靠
具体定位

5090 用来：

跑主 LLM
跑 embedding / retrieval（如果需要）
开发期临时跑 ComfyUI 生成角色资产
不建议

不要在同一时刻既拿它稳定跑在线 LLM，又同时用来大规模出图。

结论：

开发期：5090 可兼顾 LLM 与 ComfyUI
内测期：5090 应优先稳定服务 LLM
6.4 Emotion Engine（新增重点）

这是 Sober AI 比 YeYe AI 关键得多的新层。

LLM 不应该只输出一句文本，还应该输出：

她当前情绪
语气强度
表情状态
行为状态

例如：

{
  "text": "今天是不是很累？要不要先休息一下。",
  "emotion": {
    "warm": 0.8,
    "care": 0.9,
    "shy": 0.1
  },
  "avatar_state": {
    "mode": "speaking",
    "expression": "gentle",
    "micro_motion": "slight_head_tilt"
  }
}
6.5 TTS 层
第一阶段要求
可自部署
支持情绪语气
支持 NSFW
延迟可控
推荐原则

你截图里提到 Qwen3-TTS，这一类是可以先试的。

但更重要的是你要设计成：

TTS Provider 可替换

不要把项目写死到某一个声音模型。

推荐接口设计

例如：

generateSpeech({
  text,
  voiceId,
  emotion,
  speed,
  style
})

这样以后可以切：

Qwen3-TTS
IndexTTS2
Fish Speech
GPT-SoVITS
6.6 Avatar 层（最关键的表现层）
第一阶段的正确定位

不是完整 3D Avatar。

而是：

真人感 AI Avatar 表现层

分成三部分：

A. Idle 状态
呼吸感
轻微头动
眨眼
眼神变化
环境微循环
B. Thinking 状态

这是很关键的体验设计。

用户说完后，角色不要傻站着不动，而应表现为：

眼神略微偏移
轻微思索
呼吸存在
也许看向下方/侧方

这能把“等待”变成“她在想”。

C. Speaking 状态
口型同步
表情变化
轻微动作
语音同步
D. Special Motion 状态

这是以后扩展用：

跳舞
换装展示
特定剧情短片

这些不要实时生成，而是预制或半预制。
